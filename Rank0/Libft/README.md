# Libft

## Description

Libft は、42 の最初期に作成する C 言語の静的ライブラリである。
標準 C ライブラリでよく使われる関数を自分で再実装し、その上に文字列生成、ファイルディスクリプタへの出力、単方向連結リストを扱う関数を追加している。

このプロジェクトの目的は、便利な関数を「使える」だけでなく、内部でどのようにメモリを読み書きし、どこで確保し、どこで解放すべきかを理解することである。
今後の 42 課題では、この `libft.a` を土台として使う場面が多いため、挙動の安定性、メモリ管理、境界条件の扱いを特に意識して実装している。

このリポジトリが生成する成果物は、実行ファイルではなく静的ライブラリ `libft.a` である。
他の C プログラムから `libft.h` を include し、`libft.a` とリンクして使用する。

## Instructions

### 必要なもの

- C コンパイラ: `cc`
- アーカイバ: `ar`
- `make`
- コンパイルフラグ: `-Wall -Wextra -Werror`

### ビルド

```sh
make
```

成功すると、リポジトリ直下に `libft.a` が作成される。

### 生成物の削除

オブジェクトファイルだけを削除する。

```sh
make clean
```

オブジェクトファイルと `libft.a` を削除する。

```sh
make fclean
```

完全に削除してから再ビルドする。

```sh
make re
```

### Makefile の読み方

このプロジェクトでは、`Makefile` にビルド手順をまとめている。
`make` と入力すると、`Makefile` の中に書かれたルールに従って、自動で `.c` ファイルをコンパイルし、最後に `libft.a` を作成する。

主な変数:

- `NAME = libft.a`: 最終的に作るライブラリの名前
- `SRCS`: コンパイル対象の `.c` ファイル一覧
- `OBJS = $(SRCS:.c=.o)`: `.c` を `.o` に置き換えたオブジェクトファイル一覧
- `CC = cc`: 使用する C コンパイラ
- `CFLAGS = -Wall -Wextra -Werror`: コンパイル時に使う警告オプション

`CFLAGS` の意味:

- `-Wall`: よくある警告を有効にする
- `-Wextra`: `-Wall` だけでは出ない追加の警告も有効にする
- `-Werror`: 警告をエラーとして扱う

42 の課題では、警告が残っているコードは安全とはみなされない。
そのため、`-Werror` によって「警告が 1 つでも出たらコンパイル失敗」にしている。

主なルール:

- `all`: デフォルトのルール。`libft.a` を作る
- `$(NAME)`: `libft.a` を作るためのルールである
- `%.o: %.c`: `.c` ファイルから `.o` ファイルを作るためのパターンルールである
- `clean`: `.o` ファイルを削除する
- `fclean`: `.o` ファイルと `libft.a` を削除する
- `re`: `fclean` のあとに `all` を実行して作り直す

`ar rcs` の意味:

- `ar`: 複数の `.o` ファイルをまとめて静的ライブラリを作るコマンドである
- `r`: ライブラリ内のファイルを追加または置き換える
- `c`: ライブラリが存在しない場合に新しく作成する
- `s`: ライブラリの索引を作り、リンクしやすくする

つまり、次の行は「すべてのオブジェクトファイルをまとめて `libft.a` を作る」という意味である。

```make
ar rcs $(NAME) $(OBJS)
```

`%.o: %.c` の中にある `$<` と `$@` は、Makefile の自動変数である。

- `$<`: 依存元のファイル。この場合は `.c` ファイルである
- `$@`: 作成するファイル。この場合は `.o` ファイルである

そのため、次の行は「各 `.c` ファイルを、同じ名前の `.o` ファイルにコンパイルする」という意味になる。

```make
$(CC) $(CFLAGS) -c $< -o $@
```

ここで使われているコンパイルオプション:

- `-c`: リンクまでは行わず、オブジェクトファイル `.o` だけを作る
- `-o`: 出力ファイル名を指定する

`.PHONY` は、`clean` や `fclean` のように実ファイル名ではなく「コマンド名として使いたいルール」を明示するためのものである。
たとえば `clean` という名前のファイルが偶然存在しても、`make clean` が正しく削除コマンドとして動くようにしている。

`make` コマンド側でよく使う指定:

- `make`: 最初のルールを実行する。この Makefile では `all` が実行される
- `make all`: 明示的に `all` ルールを実行する
- `make clean`: 中間生成物の `.o` だけを消す
- `make fclean`: `.o` と `libft.a` を消す
- `make re`: すべて消してから作り直す
- `make -n`: 実際には実行せず、実行される予定のコマンドだけを見る
- `make -B`: 更新日時に関係なく、強制的に作り直す

「不要な再リンク」とは、ソースファイルが変わっていないのに `make` をもう一度実行しただけで `ar rcs` が走り、`libft.a` が作り直されてしまう状態のことである。
この Makefile では、`libft.a` が `$(OBJS)` に依存しているため、`.c` が変更されて `.o` が更新されたときだけライブラリを作り直すようにしている。
確認するときは、次のように `make` を 2 回実行する。

```sh
make
make
```

2 回目にコンパイルや `ar rcs` が表示されなければ、不要な再リンクは起きていない。

### 自分のプログラムから使う例

`main.c` で `libft.h` を include している場合は、次のようにリンクできる。

```sh
cc -Wall -Wextra -Werror main.c -L. -lft -I.
```

このコマンドの意味:

- `cc`: C コンパイラを起動する
- `-Wall -Wextra -Werror`: Makefile と同じく、警告を厳しく確認する
- `main.c`: コンパイルしたい自分のソースファイルである
- `-L.`: ライブラリを探す場所に、現在のディレクトリ `.` を追加する
- `-lft`: `libft.a` をリンクする
- `-I.`: ヘッダファイルを探す場所に、現在のディレクトリ `.` を追加する

`-lft` は少し特殊で、実際には `libft.a` や `libft.so` のような名前のライブラリを探す。
`lib` と `.a` を省いた部分を書いているため、`libft.a` をリンクしたい場合は `-lft` になる。

例:

```c
#include "libft.h"
#include <stdio.h>

int	main(void)
{
	printf("%zu\n", ft_strlen("libft"));
	return (0);
}
```

## Library Details

このライブラリは、大きく 3 つのグループに分かれている。

### 1. libc 関数の再実装

標準ライブラリの基本的な関数を、`ft_` プレフィックス付きで再実装している。
挙動は man page の説明に合わせ、外部関数に頼らず、バイト列や文字を直接走査して処理する。

文字判定・変換:

- `ft_isalpha`
- `ft_isdigit`
- `ft_isalnum`
- `ft_isascii`
- `ft_isprint`
- `ft_toupper`
- `ft_tolower`

メモリ操作:

- `ft_memset`
- `ft_bzero`
- `ft_memcpy`
- `ft_memmove`
- `ft_memchr`
- `ft_memcmp`
- `ft_calloc`

文字列操作:

- `ft_strlen`
- `ft_strlcpy`
- `ft_strlcat`
- `ft_strchr`
- `ft_strrchr`
- `ft_strncmp`
- `ft_strnstr`
- `ft_strdup`
- `ft_atoi`

特に `ft_memmove` は、コピー元とコピー先の領域が重なっている場合でも正しく動くように、コピー方向を切り替える必要がある。
`ft_calloc` と `ft_strdup` はメモリ確保を行うため、確保失敗時には `NULL` を返す。

### 2. 追加関数

libc には同じ形では存在しない、42 の以降の課題でもよく使う補助関数である。
多くの関数は新しい文字列や配列を `malloc` で確保して返すため、呼び出し側で適切に `free` する必要がある。

文字列を作る関数:

- `ft_substr`: 文字列の一部を切り出して新しい文字列を作る
- `ft_strjoin`: 2 つの文字列を連結した新しい文字列を作る
- `ft_strtrim`: 先頭と末尾から指定文字集合を取り除いた新しい文字列を作る
- `ft_split`: 区切り文字で分割した文字列配列を作る
- `ft_itoa`: `int` を文字列表現に変換する
- `ft_strmapi`: 各文字に関数を適用し、結果を新しい文字列として返す

文字列を直接処理する関数:

- `ft_striteri`: 各文字のアドレスに関数を適用し、元の文字列を必要に応じて変更する

ファイルディスクリプタへ出力する関数:

- `ft_putchar_fd`
- `ft_putstr_fd`
- `ft_putendl_fd`
- `ft_putnbr_fd`

`ft_split` は、途中の `malloc` が失敗した場合に、それまで確保したメモリを解放してから `NULL` を返す必要がある。
このような処理は、C における安全なエラーハンドリングを学ぶために重要だ。

### 3. 単方向連結リスト

`libft.h` では、次の構造体を定義している。

```c
typedef struct s_list
{
	void			*content;
	struct s_list	*next;
}	t_list;
```

`content` は `void *` なので、文字列、構造体、整数を格納したメモリなど、任意のデータへのポインタを保持できる。
`next` は次のノードを指し、最後のノードでは `NULL` になる。

実装しているリスト関数:

- `ft_lstnew`: 新しいノードを作る
- `ft_lstadd_front`: リストの先頭にノードを追加する
- `ft_lstadd_back`: リストの末尾にノードを追加する
- `ft_lstsize`: ノード数を数える
- `ft_lstlast`: 最後のノードを返す
- `ft_lstdelone`: 1 つのノードとその content を削除する
- `ft_lstclear`: リスト全体を削除し、先頭ポインタを `NULL` にする
- `ft_lstiter`: 各ノードの content に関数を適用する
- `ft_lstmap`: 各 content に関数を適用した新しいリストを作る

リスト関数では、ノードそのものの所有権と `content` の所有権を分けて考えることが大切である。
`ft_lstdelone` と `ft_lstclear` は、受け取った `del` 関数を使って `content` を解放し、その後でノードを解放する。
一方で、追加や走査を行う関数は、基本的に `content` の中身を勝手に解放しない。

## Algorithm and Data Structure

このプロジェクトでは、以下の Data structure（データ構造）と Algorithm（アルゴリズム）の設計と実装を行っている。ピア評価 (defense) の際にも、これらの選択意図をしっかり説明できるように詳細を記載しておく。

### Data structure (データ構造)

**単方向連結リスト (Singly Linked List)**
`libft` では、単方向連結リストを扱うための `t_list` 構造体を実装している。
- **柔軟性**: `void *content` を持つことで、文字列から複雑な構造体まで、あらゆる型のデータを格納できる汎用的なデータ構造になっている。
- **メモリ管理の分離**: ノード自体のメモリ領域と、`content` が指すメモリ領域の所有権を分離して管理することが重要である。削除処理 (`ft_lstdelone` や `ft_lstclear`) では、関数ポインタ `void (*del)(void *)` を受け取ることで、格納されたデータの型に応じた適切なメモリ解放 (`free`) を行える設計にしている。
- **計算量**: 先頭への追加 (`ft_lstadd_front`) は O(1) で処理できる反面、末尾への追加 (`ft_lstadd_back`) や全体サイズの取得 (`ft_lstsize`) には O(N) のリスト走査が必要になるという特長（トレードオフ）がある。

### Algorithm (アルゴリズム)

**メモリ領域のオーバーラップ検知と安全なコピー (`ft_memmove`)**
コピー元 (`src`) とコピー先 (`dst`) のメモリ領域が重なっている場合、前から順番に単純コピーするとデータが上書きされ、破壊される危険がある。
- **アルゴリズム**: ポインタのアドレスを比較し、`dst < src` の場合は安全に「前（先頭）から」コピーする。逆に `dst > src` の場合は、「後ろ（末尾）から」逆順にコピーすることで、未コピーのデータを上書きしないようにする安全なコピーアルゴリズムを採用している。

**文字列と数値の相互変換 (`ft_atoi`, `ft_itoa`)**
- **`ft_atoi`**: 文字列を先頭から走査して、空白文字をスキップし、必要に応じて符号 (+ / -) を処理した後、数字が続く限り `result = result * 10 + (char - '0')` のアルゴリズムを用いて10進数として蓄積する。
- **`ft_itoa`**: まず数値の桁数と符号から文字列に必要なバッファサイズを計算し、`malloc` でメモリを確保する。その後、文字列の末尾から先頭に向かって剰余演算 (`n % 10`) と除算 (`n / 10`) を用いて1桁ずつ文字を構築していく計算アルゴリズムを使っている。

**安全な文字列分割 (`ft_split`)**
- 指定された区切り文字で文字列を分割するアルゴリズムである。
- 最初に文字列全体を走査して単語数をカウントし、必要な配列のポインタ要素数を求める。
- その後配列を作成し、単語ごとにメモリを確保 (`malloc`) して文字をコピーしていく。
- **フェイルセーフ**: 途中の単語のメモリアロケーションが失敗した場合は、そのまま終了するとメモリリークが発生する。そのため、それより前に確保したすべての単語のメモリを `free` し、最後に配列本体も `free` してから `NULL` を返す、という堅牢なエラーハンドリングの仕組みを取り入れている。

**文字列の逐次検索 (`ft_strnstr`)**
- 指定された長さの範囲内で部分文字列（needle）を探すため、文字を1文字ずつ比較しながら進める逐次検索（ナイーブなパターンマッチング）アルゴリズムを実装している。
